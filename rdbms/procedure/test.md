PART 1 – 2 MARK QUESTIONS
1. Define Operating System.
An Operating System (OS) is system software that acts as an intermediary between a user of a computer and the computer hardware. Its primary goals are to make the computer system convenient to use and to manage hardware resources (CPU, memory, I/O) efficiently.
2. What are System Calls?
System calls provide the programming interface to the services provided by the operating system. They act as a bridge, allowing user-level processes to request privileged operations (like file I/O or process creation) from the OS kernel, triggering a switch from user mode to kernel mode.
3. Define CPU Scheduling.
CPU scheduling is the process of determining which process in the ready queue gets allocated the CPU for execution while another process is paused (e.g., waiting for I/O). The goal is to maximize CPU utilization and throughput.
4. Define Deadlock.
A deadlock is a situation where a set of processes are blocked permanently because each process is holding a resource and waiting to acquire a resource held by another process in the set, creating a circular dependency.
5. What is Paging in Memory Management?
Paging is a memory management scheme that eliminates the need for contiguous allocation of physical memory. It divides physical memory into fixed-size blocks called frames and logical memory into blocks of the same size called pages.
6. Define Address Binding.
Address binding is the process of mapping a logical (virtual) address generated by the CPU to a physical address in the main memory (RAM). This can happen at three stages: compile time, load time, or execution time.
7. What is the use of Semaphore?
A semaphore is an integer variable used for process synchronization to solve the critical section problem. It is accessed only through two standard atomic operations: wait() (or P) which decrements it, and signal() (or V) which increments it.
8. What is an Access Matrix?
An access matrix is an abstract security model of protection state in computer systems. It is represented as a grid where rows represent domains (users or processes), columns represent objects (files, printers), and cells contain the access rights (read, write, execute) the domain has over the object.
PART 2 – 5 MARK QUESTIONS
1. Differentiate between User View and System View of Operating System.
| Feature | User View | System View |
|---|---|---|
| Primary Goal | Ease of use, convenience, and high performance. | Efficient resource allocation and hardware management. |
| Perspective | Looks at the OS from the outside (interface level). | Looks at the OS from the inside (hardware interaction). |
| Resource Focus | Monopolizes resources for the user (in single-user PCs) or focuses on fair sharing (in mainframes). | Acts as a Resource Allocator (CPU time, memory space, file storage) among competing programs. |
| Control Aspect | Assumes the system works seamlessly without worrying about the background processes. | Acts as a Control Program to manage execution of user programs, prevent errors, and handle I/O devices safely. |
2. Discuss Deadlock Prevention, Avoidance and Recovery Methods.
 * Deadlock Prevention: Ensures a deadlock never occurs by restraining how requests can be made. It works by invalidating at least one of the four necessary Coffman conditions:
   * Mutual Exclusion: Make resources sharable (not always possible).
   * Hold and Wait: Require a process to request all resources at once before execution.
   * No Preemption: If a process holding resources requests another it cannot immediately get, it must release its current resources.
   * Circular Wait: Impose a strict linear ordering of resource types.
 * Deadlock Avoidance: The OS uses algorithms (like Banker’s Algorithm) to dynamically examine the resource allocation state. It only grants a resource request if doing so leaves the system in a Safe State (a sequence where all processes can finish).
 * Deadlock Recovery: If a deadlock occurs, the OS must break it by:
   * Process Termination: Aborting all deadlocked processes, or aborting them one at a time until the deadlock breaks.
   * Resource Preemption: Temporarily taking resources away from processes and giving them to others, which requires rolling back the preempted process to a safe state.
3. Explain Inter-Process Communication (IPC) with a suitable example.
Inter-Process Communication (IPC) is a mechanism that allows cooperating processes to exchange data and synchronize their actions. There are two primary models:
 * Shared Memory: A region of memory is shared between processes. Processes can read and write to this area as if it were regular memory. It is very fast but requires explicit synchronization (like semaphores) to avoid race conditions.
 * Message Passing: The OS handles communication via a message queue using send(message) and receive(message) system calls. Useful for distributed systems.
 * Example (Producer-Consumer Problem): A compiler (Producer) generates assembly code and places it into a shared memory buffer. The assembler (Consumer) reads the code from the buffer. IPC ensures the producer doesn't overwrite full buffers and the consumer doesn't read empty ones.
4. Describe File Access Methods and File Allocation Methods.
File Access Methods: How data is read from a file.
 * Sequential Access: Information is processed in order, one record after another (e.g., magnetic tapes).
 * Direct (Relative) Access: Files are viewed as a numbered sequence of blocks. The OS can jump to any block instantly (e.g., modern databases on disks).
File Allocation Methods: How disk blocks are allocated to files.
 * Contiguous Allocation: Each file occupies a set of continuous blocks on the disk. Excellent read performance, but suffers from severe external fragmentation (wasted space).
 * Linked Allocation: Each file is a linked list of disk blocks scattered anywhere on the disk. Solves fragmentation, but direct access is impossible (must traverse pointers).
 * Indexed Allocation: Brings all pointers together into one specific index block for each file. Supports direct access and no external fragmentation, but wastes space on index blocks for very small files.
PART 3 – 10 MARK QUESTIONS
1. Explain Different CPU Scheduling Algorithms with Suitable Examples.
CPU scheduling determines the execution order of processes in the ready queue. The primary goals are maximizing CPU utilization and minimizing turnaround, waiting, and response times.
 * First-Come, First-Served (FCFS):
   * Concept: The process that requests the CPU first is allocated the CPU first. It is strictly non-preemptive.
   * Example: If P1 (burst time 24), P2 (3), and P3 (3) arrive in that order, P1 holds the CPU for 24 units, forcing short processes to wait.
   * Drawback: Convoy Effect – short processes get stuck behind long ones, causing high average waiting times.
 * Shortest Job First (SJF):
   * Concept: Associates each process with the length of its next CPU burst. The CPU is assigned to the process with the shortest burst.
   * Versions: Can be Non-preemptive or Preemptive (known as Shortest Remaining Time First - SRTF).
   * Advantage: Provably optimal for giving the minimum average waiting time.
   * Drawback: Impossible to know the exact length of the next CPU burst in advance.
 * Priority Scheduling:
   * Concept: A priority number is assigned to each process. The CPU is allocated to the highest priority process.
   * Drawback: Starvation – low-priority processes may wait indefinitely if high-priority processes keep arriving.
   * Solution: Aging – gradually increasing the priority of processes that wait in the system for a long time.
 * Round Robin (RR):
   * Concept: Designed for time-sharing systems. Each process gets a small unit of CPU time called a time quantum (e.g., 10-100 milliseconds).
   * Mechanism: Once the quantum expires, the process is preempted and added to the end of the ready queue.
   * Advantage: Excellent response time and fair share of CPU for all processes.
2. Describe Virtual Memory Management.
Virtual memory is a technique that allows the execution of processes that are not completely in the main memory. It abstracts main memory into a large, uniform array of storage, separating logical memory from physical memory. This allows programs to be larger than the actual physical RAM.
 * Demand Paging:
   * The core mechanism of virtual memory. Pages are only loaded from the disk into physical memory when they are demanded during execution.
   * When the CPU tries to access a page not currently in RAM, a Page Fault occurs.
   * The OS traps the error, locates the page on the disk, loads it into a free frame in physical memory, updates the page table, and restarts the instruction.
 * Page Replacement:
   * If a page fault occurs and physical memory is full, the OS must swap out an existing page to make room. Page replacement algorithms decide which page to evict.
 * Page Replacement Algorithms:
   * FIFO (First-In-First-Out): Replaces the oldest page in memory. Prone to Belady’s Anomaly (increasing frames can increase page faults).
   * LRU (Least Recently Used): Replaces the page that has not been used for the longest period of time. Highly effective and widely used.
   * Optimal: Replaces the page that will not be used for the longest time in the future. Impossible to implement, used only as a theoretical benchmark.
 * Thrashing: A critical performance failure where a system spends more time swapping pages in and out of disk than executing actual instructions, usually caused by too many programs running simultaneously with insufficient physical memory.
3. Explain Process Synchronization.
Process synchronization ensures the orderly execution of cooperating processes that share data, preventing data inconsistency.
 * The Race Condition: A situation where several processes access and manipulate the same shared data concurrently. The final value of the data depends on which process finishes last, leading to unpredictable bugs.
 * The Critical Section Problem: A critical section is a segment of code where a process modifies shared variables, tables, or files. The problem is designing a protocol where only one process is allowed in its critical section at a time.
 * Requirements for a Solution:
   * Mutual Exclusion: If Process P1 is in its critical section, no other process can enter theirs.
   * Progress: If no process is in its critical section and some wish to enter, the selection cannot be postponed indefinitely.
   * Bounded Waiting: A limit must exist on how many times other processes can enter their critical sections after a process has made a request to enter its own.
 * Synchronization Tools:
   * Mutex Locks: The simplest tool. A process must acquire() the lock before entering the critical section and release() it upon exiting.
   * Semaphores: Integer variables used for complex signaling. A binary semaphore acts like a mutex. A counting semaphore controls access to a resource with multiple instances.
 * Classical IPC Problems:
   * Dining Philosophers: Models resource allocation avoiding deadlock and starvation.
   * Readers-Writers: Ensures multiple readers can read simultaneously, but a writer requires exclusive access.
4. Explain File Management System.
The File Management System is the component of the OS responsible for creating, organizing, securing, and deleting files. It provides a logical view of information storage, hiding the complex physical properties of storage devices.
 * File Attributes: Every file has metadata attached to it, including Name, Identifier (unique number), Type, Location (pointer to device/blocks), Size, Protection (access control), and Time/Date of creation and modification.
 * Standard File Operations:
   * Create: Find space and make an entry in the directory.
   * Write: OS maintains a write pointer for the location of the next write.
   * Read: OS maintains a read pointer.
   * Reposition (Seek): Move the current file pointer to a specific location.
   * Delete: Free disk space and erase the directory entry.
 * Directory Structure: Organizes files for quick retrieval.
   * Single-Level: All files in one directory (naming collisions occur).
   * Two-Level: Separate directory for each user.
   * Tree-Structured: Current standard (like Windows/Linux). Root directory branches into subdirectories, allowing users to create their own subdirectories.
   * Acyclic-Graph: Allows directories to share subdirectories and files (links/shortcuts).
 * Protection and Security:
   * The OS uses an Access Control List (ACL) to regulate who can access a file and in what way.
   * Permissions are generally broken down into Read, Write, and Execute.
   * Passwords and encryption are also managed by this system to protect data at rest.
